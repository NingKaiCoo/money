# 经验教训总结 · 基金回本作战

> **用途**：沉淀每次操作的踩坑教训与获利经验、以及每周复盘结论。遇到同类有规律可循的情形，先翻本文件再决策，避免重复交学费。
>
> **维护规则**：
> 1. 每次出现可复用的规律（无论盈亏）就追加一条，标注日期与触发场景；
> 2. 每周一复盘后，把当期结论写入「三、每周复盘结论」；
> 3. 条目只增不删；若某条已被新策略覆盖，在该条下注明"已被 XX 覆盖"而非直接删；
> 4. 本文件是**经验参考库（按需查阅）**，不纳入"发截图必读 3 份"的强制清单；但若与手册/复检/诊断冲突，以最新策略文件为准，并在本文件标注冲突点。
>
> **如何使用**：决策前先扫「一、反面教训」看是否踩过同类坑；做对的事对照「二、正面经验」保持；每周看「三」校准方向。

## 一、反面教训（踩过的坑，禁止再犯）

### L1 · 信号①判定口径混淆：单日涨幅 ≠ 自低点累计反弹（2026-08-07）
- **现象**：① 把"单只自近期低点累计反弹 +15~20%"误说成"当日涨幅"，与截图里的单日 +3.13% 混为一谈；② 核对是否止盈时，错看"持有收益是否回正"，而非"距低点累计反弹幅度"。
- **后果**：险些在东方AI 已触发止盈信号时仍给"持有不动"，误导操作。
- **正确做法**：信号①只看**自阶段低点的累计反弹幅度**；单日 +3% 属正常波动、非风险信号、不减。核对止盈一律用"距低点反弹%"而非"持有收益%"。

### L2 · 未经"同步"擅自 git 推送（2026-08-06 前后）
- **现象**：用户未下"同步"指令，AI 自行 commit + push。
- **后果**：用户批评"我没让你同步你就别自己同步"。
- **正确做法**：本地改动随便落，**未经用户明确说"同步"，绝不 git 推送**。

### L3 · 发截图分析未读全 3 份文件（2026-08-07 14:44）
- **现象**：用户发持仓截图，AI 只读已删除的"操作记录.md"就给建议，漏读手册/复检/诊断。
- **后果**：建议脱离规则依据，口径偏差。
- **正确做法**：**凡发截图做分析/操作，必须一次性 Read 全 3 份文件**（每日作战手册.html + 资金策略复检.html + 最初持仓诊断.html），高于效率优先级。

### L4 · 回复不按手册第7节格式、漏维度（2026-08-07 15:07）
- **现象**：给当日策略时未用标准第7节格式，漏了"5-20日趋势"等维度。
- **后果**：用户指出"昨天约定的规则全没了"。
- **正确做法**：严格按手册第7节标准回复格式（多向盘面→定级→策略更新→逐只操作→跨板块→明日观察），不漏维度。

### L5 · 只给卖出指令、不说清资金去向（2026-08-07）
- **现象**：减东方AI 只说了"卖"，没同步讲这笔钱下一步怎么部署。
- **后果**：违反防呆红线②，用户不清楚钱去哪。
- **正确做法**：每一次减/加动作，必须同时说明"去向"——当天 6 维度择优去哪，或明确"回流周转金池待命"。

### L6 · 减仓后资金默认转宽基/短债（2026-08-06）
- **现象**：误把卖回资金默认转去宽基/短债，而非回流周转金池。
- **后果**：偏离"回本途中科技引擎全开"的方案B，拖慢回本。
- **正确做法**：卖回资金**回流周转金池待命**（买扣钱、卖加钱），不自动转其他品种；是否切换非科技板块需显式信号支持。

### L7 · 台账真实盈亏会计缺陷（2026-08-06~07，已弃用）
- **现象**：① 用"持有收益"记账，卖出后收益清零，掩盖真实亏损；② 后加"现盈利资金""当日盈亏"列，仍复杂难维护；③ 文件被反复改、引用散落。
- **后果**：用户指出持仓收益卖出即清零掩盖真实亏损；最终放弃整个台账文件。
- **正确做法**：**不维护任何持仓/余额台账文件**；持仓市值、当日盈亏、持有收益一律以每日持仓截图为准，策略严格遵循手册+复检（读全 3 份）。

### L8 · 切板块不追单日脉冲：必须验趋势/低点/估值（2026-08-07）
- **现象**：用户质疑"切非科技板块是不是只看当日"——上一条回复用"当日信号指向更强方向"措辞，易误解为只看单日涨跌就切；而文件里只有 14 方向定性买点，缺"切板块前置硬闸门"。
- **后果**：若只看单日领涨就建议切过去，变成追涨杀跌、接飞刀。
- **正确做法**：任何从科技切向非科技方向的动作，必须**同时满足**——① 该方向近 5–20 日呈上升趋势且站上 5/20 日线；② 非单日脉冲（当日领涨但前几日无趋势=不切）；③ 距阶段低有空间、估值分位未到 90%+。三者缺一，宁可不动。与手册维度②(5-20日趋势)口径一致，但升级为"**切换前置硬条件**"。
- **状态**：已与 L9 合并升级为《每日作战手册》第2节「切板块前置硬闸门」5 条前置条件（趋势/非脉冲/位置/持续性/多方综合），2026-08-07。

### L9 · 非主线方向不持久，切之前须验"持续性 + 多方综合"（2026-08-07）
- **现象**：用户经验指出——很多非主线方向（轮动题材）切过去后不长久，短线脉冲难以贡献持续回本，盲目切反而增加摩擦与踏错节奏。
- **后果**：若只看"某方向当日/短期更强"就切，易陷入"追热点→不持续→再切回"的来回损耗，反而拖累回本效率。
- **正确做法**：切板块不止通过 L8 的趋势/位置/估值门槛，还须额外验"主线成色 / 持续性"——该方向是否有政策 / 景气 / 资金共振的持续性支撑，而非一两日轮动脉冲；并做多方综合（趋势 + 估值 + 持续性 + 催化 + 资金五维同向）后才动。已并入《手册》第2节前置闸门第④⑤条。

### L10 · 抗遗忘：操作前"对齐锚点"强制首步（2026-08-07）
- **现象**：用户担忧"聊着聊着就忘、不认真、不把钱当回事"——长对话中 AI 易飘、漏读文件、遗忘铁律，凭印象接话而非回文件核对（如 8/7 曾漏判信号①、一度不读全文件）。
- **后果**：若不设强制可见锚点，用户无法快速识别 AI 是否走偏，信任崩塌；轻则建议脱离规则，重则误导真实资金操作。
- **正确做法**：已写入《手册》第7节——每次给操作 / 策略指令，回复第一段必须显式完成"对齐锚点"四步：① 复述持仓快照（**以用户截图为准**，不靠记忆）；② 声明已 Read 全 3 份文件；③ 扫 L1–L10 是否踩同类坑；④ 重申"真实资金、每分当真"。**四步未显式出现，视为本条回复不合格**。用户可随时戳"你这步有没有读全文件 / 过闸门"要求当场纠正并重新核对。

## 二、正面经验（做对的事，保持）

### G1 · 方案B 速度优先是回本最快路径
回本途中科技引擎全开，减仓只认 4 条风险信号（①自低点反弹+15~20% ②单周>15%拥挤 ③破20日线 ④估值分位90%+），不因人慌而乱砍。

### G2 · 多向验证 + 本金安全优先
每次决策多向验证（同时看多/空论据）、想清"错了最大亏多少"、不追高、不幻视、不编造。

### G3 · 防呆红线① 不缩视野到持仓板块
分析时扫全市场 14 个方向（医药/有色/券商/港股/红利等），不只在现有持仓板块里打转。

### G4 · 用户授权边界清晰
用户定调：① 原则=尽快回本且盈利（唯一目标）；② 市场分析与策略决策归 AI 判断、用户只管按指令点；③ 真实资金、谨慎优先；④ **科技占比多少不是约束目标**——用户明确"不管科技占比多少"，集中度/分散度不参与决策，一切以"能否尽快回本盈利"为准。

### G5 · 用户授权：判断能增加回本概率即可切非科技（须过前置闸门）
- 用户定调（2026-08-07）：具体策略由 AI 判断并决策；若判断"切向非科技 / 跨主线能增加回本概率"，即可执行切换——但必须过《手册》第2节「切板块前置硬闸门」（L8+L9 的 5 条前置条件），谨防追涨杀跌、谨防非主线不持久。
- 这是"速度优先(方案B)"框架下对"买 / 切信号"的授权补强：从"只在风险信号减、只在买信号加"扩展到"AI 经多维度验证认为能加速回本即可主动切"，但闸门不松。
- 补充（2026-08-11）：用户明确"不管科技占比多少"，故切板块的动机**不是"压集中度/降科技"**，而是纯粹"能否提升回本概率"。集中度从不是用户的目标函数——决策时既不必为"满足分散"而切，也不必为"保持高集中"而僵化，一律只看回本概率。与 G4 第④条一致。

### G6 · 不追涨杀跌是永久铁律（不受「尽快回本」目标豁免）（2026-08-11）
- **用户定调**：目标=尽快回本且盈利（单目标、不管科技占比，见 G4④），但**「不追涨杀跌」是与目标并列的永久底线，绝不因想快点回本而松动**——目标再急，也不能成为追高买入 / 恐慌杀跌的理由。
- **定义**：① 追涨=因某标的/板块短期涨得快就买入（接飞刀、追高）；② 杀跌=因某标的短期跌得多就恐慌卖出（非信号驱动的砍仓）。
- **正确做法**：买/切一律过《手册》第2节前置闸门 5 条（趋势/非脉冲/位置/持续性/多方综合）——**涨得快≠能买**；卖/减一律只认方案B 4 条风险信号（信号①自低点+15~20% / ②单周>15%拥挤 / ③破20日线 / ④估值90%+）——**跌得多≠能卖**。目标越急，越要守这两条闸；「尽快回本」是目的，「不追涨杀跌」是纪律，二者不冲突、纪律优先。

### G7 · 用户授权：对全市场所有基金拥有完整操作权限（建仓/清仓/加仓/减仓/切板块，含现有 4 只 + 全市场任意场外基金）（2026-08-11 扩权）
- **用户定调（2026-08-11 扩权）**：我对基金的操作权限为**全频谱**——对**现有 4 只持仓 + 全市场任意场外基金（指数/ETF联接/主题）**，均有权自主决策并执行「**建仓（新建仓）/ 加仓 / 减仓 / 清仓（某只全清或整体清）/ 切板块（跨方向切换）**」等一切操作；决策由 AI 定（买/卖/清哪只、各多少、什么触发），最终你在 App 手动下单（手册第0节「我不能替你下单」）。即操作集从「现有持仓内调/减/切 + 全市场新建仓」扩为「全市场所有基金的全频谱操作」。
- **边界（铁律不变）**：扩的是「能操作什么」，不是「可以乱操作」。任何操作仍须过对应纪律闸门——买/切过《手册》第2节前置硬闸门 5 条（趋势/非脉冲/位置/持续性/多方综合）；减/清只认方案B 4 条风险信号（止盈+15~20% / 单周>15%拥挤 / 破20日线 / 估值分位90%+）或破位止损逻辑；不追涨杀跌(G6) + 多向验证 + 想清"错了最大亏多少"。与防呆红线①（不缩窄为现有持仓板块）一致——任何闸门/信号一律不松。
- **执行边界**：① 清仓（含某只全清）属极端减仓，仍须过方案B 减仓信号 + 想清"全清后若踏空/反转最大亏多少"；② 新买入 C 类须过 7 天赎回费校验（不满 7 天不卖）；③ 决策由 AI 定，最终下单仍由用户在 App 执行（见手册第0节）。

### G8 · 用户授权：日常操作决策由 AI 自主拍板、无需每次请示（2026-08-11）
- **用户定调（2026-08-11）**："这是你的事，由你决定"——在 G7 全频谱权限基础上，进一步明确**日常买卖/切/建/清的决策无需每次向用户确认**，AI 应主动拍板、直接给"结论 + 理由 + 触发条件"，用户只负责在 App 执行；不重复追问"要不要放观察池""要不要动"之类确认性提问。
- **边界**：① 自主决策 ≠ 破纪律——仍必须过对应闸门（买/切 5 条、减/清方案B 4 信号）、不追涨杀跌(G6)、多向验证、想清"错了最大亏多少"；② 最终下单仍由用户执行（手册第0节，系统限制，AI 不能替你交易）；③ 持仓截图等**数据输入**无法由 AI 生成，仍须用户每日 14:45 前提供，AI 拿到后自主完成全部分析决策。
- **执行**：提高主动性与结论密度，减少确认性提问；首笔新建仓 / 清仓某只等较重大动作，一句话告知"我决定 XX，理由 XX，你执行"即可，而非等待批准。
